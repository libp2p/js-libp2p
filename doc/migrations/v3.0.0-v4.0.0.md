## Keys are created and decoded asynchronously

`@libp2p/crypto` is now built on WebCrypto. The `@libp2p/crypto/keys` export
has been removed and its functions are exported from `@libp2p/crypto`.
Generating and decoding keys is async, and the key types live in
`@libp2p/interface`.

**Before**

```ts
import { generateKeyPair, privateKeyFromProtobuf, publicKeyToProtobuf } from '@libp2p/crypto/keys'

const key = await generateKeyPair('Ed25519')
const bytes = publicKeyToProtobuf(key.publicKey)
const decoded = privateKeyFromProtobuf(buf)
```

**After**

```ts
import { generateKeyPair, privateKeyFromProtobuf } from '@libp2p/crypto'

const key = await generateKeyPair('Ed25519')
const bytes = key.publicKey.toProtobuf()
const decoded = await privateKeyFromProtobuf(buf)
```

Options are passed as an object, e.g. `generateKeyPair('RSA', { bits: 2048 })`
or `generateKeyPair('ECDSA', { curve: 'P-256' })`.

Keys created by `@libp2p/crypto@5` cannot be passed to libp2p@4. Recreate them
from their protobuf bytes with `privateKeyFromProtobuf`.

## Removed crypto exports

- `@libp2p/crypto/hmac`, `/ciphers` and `/webcrypto`, `pbkdf2`, `randomBytes`, `keyStretcher` and ECDH have been removed
- `.raw` and `.equals` on keys have been removed, as have `publicKeyFromRaw`, `privateKeyFromRaw`, `publicKeyFromMultihash` and `generateKeyPairFromSeed`
- `publicKeyToProtobuf(key)` and `privateKeyToProtobuf(key)` are now `key.toProtobuf()`

To compare keys, compare their protobuf bytes with `equals` from `uint8arrays/equals`.

## PeerId public keys are protobuf bytes

`@libp2p/peer-id` no longer depends on `@libp2p/crypto`, so `peerId.publicKey`
is the protobuf-encoded key instead of a `PublicKey`. Use `publicKeyForPeer`
to get a key object. It checks that the key matches the peer id.

**Before**

```ts
const valid = await peerId.publicKey.verify(data, sig)
```

**After**

```ts
import { publicKeyForPeer } from '@libp2p/crypto'

const publicKey = await publicKeyForPeer(peerId)
const valid = await publicKey.verify(data, sig)
```

## secp256k1 is opt-in

Ed25519, RSA and ECDSA keys are supported by default. To use secp256k1 keys,
or to talk to peers that do, pass it to `createLibp2p`:

```ts
import { createLibp2p } from 'libp2p'
import { secp256k1Crypto } from '@libp2p/crypto/secp256k1'

const node = await createLibp2p({
  cryptos: [secp256k1Crypto()]
})
```

Without it a node cannot complete handshakes with peers that use secp256k1
identities and cannot verify their identify or pubsub keys. Keychain
secp256k1 keys are migrated but cannot be exported until it is configured.

Outside of libp2p, pass a loader from `createCryptoLoader([secp256k1Crypto()])`
as the `getCrypto` option of `generateKeyPair`, `publicKeyFromProtobuf`,
`privateKeyFromProtobuf` and `publicKeyForPeer`.

## Services receive a crypto loader

The configured loader is available as `libp2p.getCrypto` and as the
`getCrypto` component. Services that decode keys should pass it on so the key
types configured by the user are supported:

```ts
import { publicKeyFromProtobuf } from '@libp2p/crypto'
import type { CryptoLoader } from '@libp2p/interface'

interface MyServiceComponents {
  getCrypto?: CryptoLoader
}

class MyService {
  constructor (private readonly components: MyServiceComponents) {}

  async decode (buf: Uint8Array) {
    return publicKeyFromProtobuf(buf, { getCrypto: this.components.getCrypto })
  }
}
```

## Keychain options

`@libp2p/keychain` now uses AES-GCM and PBKDF2 from WebCrypto.

**Before**

```ts
import { keychain } from '@libp2p/keychain'

keychain({
  pass: 'not-safe-password-123456789',
  dek: { salt: 'my-salt', iterationCount: 10000 }
})
```

**After**

```ts
import { keychain } from '@libp2p/keychain'

keychain({
  password: 'not-safe-password-123456789',
  salt: 'my-salt',
  iterations: 10000
})
```

- A customized `dek.keyLength` or `dek.hash` goes in `legacyDek: { keyLength, hash }`. It is only used to read keys written by 6.x
- Stores written by 6.x are migrated the first time the keychain is used. Once migrated a store cannot be opened by 6.x, so back up the datastore first
- `findKeyById` and `findKeyByName` have been removed
- `listKeys()` is an async generator
- `importKey` returns the imported key and `removeKey` returns nothing
- `rotateKeychainPass(password)` takes only the new password

See the [@libp2p/keychain README](https://github.com/libp2p/js-libp2p/tree/main/packages/keychain#upgrading-from-6x) for details.

## Module Updates

With this release you should update the following libp2p modules if you are relying on them:

<!--Specify module versions in JSON for migration below.

```json
"@libp2p/crypto": "^6.0.0",
"@libp2p/interface": "^4.0.0",
"@libp2p/keychain": "^7.0.0",
"@libp2p/peer-id": "^7.0.0",
"libp2p": "^4.0.0",
```

Every other `@libp2p/*` module depends on `@libp2p/interface@4` and has a new
major version. Update them together.
